# 1:N 얼굴 인증 시스템 시제품 — 구현·시험·평가 보고서

- 기준 문서: 제안요청서(RFP) v0.1, 시스템 디자인 v0.1 (`docs/`)
- 범위: 하드웨어(Gemini 336 센서, 전용 단말) 제외. 센서와 사용자는 시뮬레이션으로 대체 (`faceauth/sim`)
- 실행 환경: Docker 단일 호스트, NVIDIA RTX A6000 1장(GPU 5)에 모든 GPU 서비스를 함께 배치
- 작성일: 2026-10-11. 수치는 모두 이 저장소의 스크립트로 실제 측정한 값이며, 재현 명령은 부록 A에 있습니다.

## 2. 구현 범위

### 2.1 구성

```
단말(시뮬레이터) --mTLS--> gateway(nginx, TLS 1.3, 클라이언트 인증서 필수) --> api-1 / api-2 (정책·감사)
                                                                    ├─ engine-1 / engine-2 (GPU: 검출·포즈·PAD·특징)
                                                                    ├─ search-1 / search-2 (GPU: FAISS 정확 검색)
                                                                    ├─ kms (고객별 키, crypto-shredding)
                                                                    └─ db / db-standby1 / db-standby2 (PostgreSQL 동기 복제 ANY 1)
```

설계서 §1의 계층을 그대로 구현했습니다. 원본 프레임은 메모리에서만 처리하며, 서비스 컨테이너는 읽기 전용 루트 파일시스템과
tmpfs만 씁니다. 인식 벡터는 KMS의 고객별 키로 암호화되고, 검색 복제본만 KMS로 복호화할 수 있습니다(API는 암호화·파기만 가능).

### 2.2 채택 모델

| 기능 | RFP 후보 | 채택 | 근거 |
|---|---|---|---|

### 2.3 시뮬레이션으로 대체한 것

- 센서: `SensorSim`이 사진을 640×480 RGB·Depth(mm)·IR 동기 프레임으로 렌더링합니다. 깊이 잡음, 구멍, IR 음영을 모사합니다.
- 공격: 인쇄물, 화면 재생, 경질 마스크, 실리콘 마스크, 캡처 경로 주입.
- 사용자: BIWI(실제 RGB-D 고개 회전 영상, 20명)와 CelebA 사진을 사용합니다.
- 단말: 같은 모델을 GPU 5에서 실행하고, 서명된 캡처 패킷을 mTLS로 전송합니다.

### 4.4 E4 헤드포즈 (AFLW2000-3D, BIWI)

평균 절대오차(°)이고, 검출 박스는 실제 배포와 같은 SCRFD 박스입니다. "등록 범위"는 |yaw| ≤ 40°, |pitch| ≤ 25°이며, "방향 판정"은 9방향 bin 정확도입니다.

| 모델 | AFLW2000 전체 | AFLW2000 등록 범위 / 방향 판정 | BIWI 전체 | BIWI 등록 범위 / 방향 판정 |
|---|---|---|---|---|
| 6DRepNet (일반, 300W-LP) | 3.47 | 2.28 / 0.713 | 4.30 | 3.50 / 0.478 |
| 6DRepNet360 Full-Rotation | 3.92 (FSA) | 2.65 / 0.677 | 5.15 (FSA) | **2.98 / 0.593** |
| 6DRepNet360 (300W-LP 미세조정) | 3.45 | 2.24 / 0.702 | 4.08 | 3.38 / 0.523 |

- 실제 RGB-D 고개 회전 영상인 BIWI의 등록 범위에서 6DRepNet360 Full-Rotation(FSA 크롭)이 가장 정확했습니다. 정지 사진인 AFLW2000에서는 일반 모델이 약간 낫습니다.
- 그래서 RFP 후보인 6DRepNet360을 채택했고, 단말과 서버가 같은 모델·크롭·디코딩 픽셀을 쓰도록 맞췄습니다.
- 처리 시간은 얼굴당 7.7 ms(배치 1), 1.7 ms(배치 16)입니다.

- **v1 → v2**: 초기 모델(v1)은 정면 사진으로만 학습해서, 등록에 필요한 좌·좌상·우상 방향 프레임의 33–67%를 위조로 판정했습니다.
  - BIWI의 실제 고개 회전 영상을 학습에 추가한 v2로 교체했습니다. 등록 평가 인물은 학습에서 뺐습니다.
  - 교체 후 9방향 모두에서 통과합니다.
- **미학습 공격 유형이 가장 큰 위험입니다.** 마스크를 학습하지 않은 모델은 마스크의 74–89%를 통과시켰고, 물리 검사(깊이 굴곡)도 마스크는 막지 못합니다.

  - 따라서 실제 3D 마스크를 포함한 센서 데이터 수집이 하드웨어 단계의 필수 과제입니다.

### 4.10 E10 가용성·복구

PostgreSQL 3노드(동기 복제 `ANY 1`)에서 프라이머리를 강제 종료(docker kill)하고 자동 감지·승격했습니다.

| 시나리오 | 확인된 등록 / 철회 | 손실 | RTO |
|---|---|---|---|
| 프라이머리 종료 ×3 | 7,083 / 3,532 | 0 | 7.29 s, 9.28 s, 6.30 s (감지 3.0–4.3 s 포함) |
| 스탠바이 1대 종료 | 3,414 / 1,705 | 0 | 쓰기 중단 없음 |
| 스탠바이 2대 종료 | 1,500 / 749 | 0 | 쓰기 차단(fail closed). 복귀 후 재개, 승인 조건은 완화하지 않음 |

- 5회 모두 RPO = 0이었습니다. 생존 노드에서 행 상태, outbox 이벤트, 모든 템플릿의 KMS 복호화, 철회 키 파기, 감사 해시 체인까지 다시 확인했습니다.
- 4M 템플릿 검색 색인 재구성은 89–108 s(KMS 복호화 포함)입니다. RTO 예산 안에 들어옵니다.
- 장애 전환 뒤 이미 반영한 이벤트가 사라지거나 번호가 재사용된 것을 검색 복제본이 감지하면 색인을 재구성하도록 보강했습니다.
- 한계: 단일 호스트이므로 네트워크 분할·디스크 손실은 시험하지 못했습니다.
