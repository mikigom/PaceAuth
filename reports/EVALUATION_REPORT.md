# 1:N 얼굴 인증 시스템 시제품 — 구현·시험·평가 보고서

- 기준 문서: 제안요청서(RFP) v0.1, 시스템 디자인 v0.1 (`docs/`)
- 범위: 하드웨어(Gemini 336 센서, 전용 단말) 제외. 센서와 사용자는 시뮬레이션으로 대체 (`faceauth/sim`)
- 실행 환경: Docker 단일 호스트, NVIDIA RTX A6000 1장(GPU 5)에 모든 GPU 서비스를 함께 배치
- 작성일: 2026-10-11. 수치는 모두 이 저장소의 스크립트로 실제 측정한 값이며, 재현 명령은 부록 A에 있습니다.

## 1. 요약

하드웨어를 제외한 전체 시스템을 RFP와 설계서의 구조대로 구현했습니다. Docker에서 운영 규모 갤러리(100만 명 × 4 템플릿)를 올려 시험했습니다.

- **기능·보안 요구는 시제품 수준에서 모두 구현·검증했습니다.**
  - FR-01~OPS-01 전 항목에 구현과 시험 근거가 있습니다(§3).
  - 실제 스택(실제 엔진·PAD·검색·KMS·DB)에서 보안 시험 22건이 통과했습니다(§4.11).
  - 남은 보안 공백은 센서 출처 증명이며, 하드웨어 단계 과제입니다.
- **지연·처리량**: GPU 1장으로 초당 50세션까지 목표를 충족했습니다(p95 1.16 s, p99 1.32 s). 초당 100세션에는 GPU 2장, 이중화까지 3장이 필요합니다(§4.9). 설계서가 "부하 시험으로 확정"하라고 한 GPU 수량의 근거입니다.
- **1:N 정확도 목표(FPIR 10⁻⁶에서 FNIR ≤ 1%)는 현재 데이터로 충족도 입증도 되지 않았습니다**(§4.2).
  - 공개 데이터로 만든 최대 갤러리(14.9만 명)에서 FPIR 10⁻⁴의 FNIR은 3.3%(웹 사진 1장)입니다.
  - 100만 명으로 외삽하면 FPIR 10⁻⁶ 임계값에서 FNIR 13.5%(사진 1장), 1.8%(사진 3장 평균)입니다.
  - 입증하려면 약 300만 회의 독립 비동일인 검색과 실제 키오스크 촬영 데이터가 필요합니다.
- **등록**: 시뮬레이션 사용자로는 성공률 80%, 등록 시간 p95 56 s로 목표 미달입니다(§4.8).
  - 원인 셋 중 하향 시선 품질 판정은 고쳤습니다.
  - 나머지 둘(녹화 데이터의 방향 누락, 프레임별 PAD 오거절 누적)은 이번 범위에서 고칠 수 없어 원인과 개선안을 정리했습니다.
- **PAD**: 합성 데이터에서는 학습한 공격을 모두 막지만, 학습하지 않은 마스크는 74–89% 통과시켰습니다. 실센서·실공격 데이터와 독립 시험이 하드웨어 단계의 최우선 과제입니다.
- **가용성**: DB 프라이머리 장애 시 RTO 6–9 s, RPO 0입니다(§4.10).
- **주 인식 모델**: RFP 1순위 InsightFace ViT-L/WebFace42M은 공개 가중치가 없습니다. 그래서 공개 후보 4종을 비교해 1:N이 가장 좋은 **AdaFace IR101 (WebFace12M)**을 배포했습니다(§4.1–4.2).

## 2. 구현 범위

### 2.1 구성

```
단말(시뮬레이터) --mTLS--> gateway(nginx, TLS 1.3, 클라이언트 인증서 필수) --> api-1 / api-2 (정책·감사)
                                                                    ├─ engine-1 / engine-2 (GPU: 검출·포즈·PAD·특징)
                                                                    ├─ search-1 / search-2 (GPU: FAISS 정확 검색)
                                                                    ├─ kms (고객별 키, crypto-shredding)
                                                                    └─ db / db-standby1 / db-standby2 (PostgreSQL 동기 복제 ANY 1)
```

설계서 §1의 계층을 그대로 구현했습니다.
- 원본 프레임은 메모리에서만 처리합니다. 서비스 컨테이너는 읽기 전용 루트 파일시스템과 tmpfs만 씁니다.
- 인식 벡터는 KMS의 고객별 키로 암호화됩니다. 복호화는 검색 복제본만 할 수 있고, API는 암호화와 키 파기만 할 수 있습니다.
- 모델은 Ed25519로 서명된 레지스트리에 있는 파일만, DB가 지정한 활성 버전으로 적재합니다. 해시가 다르거나 CPU로 대체 실행되는 경우에는 적재를 거부합니다.

운영 임계값은 다음과 같습니다(§4.2, §4.8).
- 식별 `FA_T_ID=0.60`: FPIR 10⁻⁶ @ 100만×4 외삽 임계값 0.597을 올린 값
- 모호성 `FA_MARGIN=0.10`
- 중복 검토 `FA_T_DUP=0.45`
- 동일인 `FA_T_SAME=0.68`

### 2.3 시뮬레이션으로 대체한 것

- 센서: `SensorSim`이 사진을 640×480 RGB·Depth(mm)·IR 동기 프레임으로 렌더링합니다. 깊이 잡음, 구멍, IR 음영을 모사합니다.
- 공격: 인쇄물, 화면 재생, 경질 마스크, 실리콘 마스크, 캡처 경로 주입.
- 사용자: BIWI(실제 RGB-D 고개 회전 영상, 20명)와 CelebA 사진을 사용합니다. 등록 시뮬레이션의 사용자는 화면 안내를 따라 고개를 돌립니다.
- 단말: 같은 모델을 GPU 5에서 실행하고, 서명된 캡처 패킷을 mTLS로 전송합니다.

## 4. 시험 결과

### 4.1 E1 얼굴 인식 1:1

InsightFace 10-fold 프로토콜, flip 포함, fp32 기준이며 괄호는 공개값입니다.

| 모델 | LFW | CFP-FP | AgeDB-30 | CALFW | CPLFW |
|---|---|---|---|---|---|
| KP-RPE ViT-B, AdaFace, WebFace12M | 99.82 (99.82) | 99.30 (99.30) | 98.10 (98.10) | 95.93 (95.93) | 95.65 (95.65) |
| **AdaFace IR101, WebFace12M (배포)** | 99.82 (99.82) | 99.24 (99.24) | 98.00 (98.00) | 96.12 (96.12) | 94.57 (94.57) |
| InsightFace R50, WebFace600K (buffalo_l) | 99.82 (99.83) | 99.26 (99.33) | 98.12 (98.23) | 95.95 | 94.48 |
| InsightFace R100, Glint360K (antelopev2) | 99.83 | 99.17 | 98.28 | 96.10 | 94.67 |
| InsightFace ViT-L, WebFace42M (RFP 1순위) | 공개 가중치 없음 | | | | |

- CVLFace 두 모델은 공개 수치를 소수 둘째 자리까지 재현했습니다.
- 1:1 벤치마크에서는 네 모델 차이가 작습니다. KP-RPE가 측면 얼굴(CPLFW)에서 1 pp 앞섭니다.
- 모델을 고른 기준은 RFP의 주 지표인 1:N입니다(§4.2).

### 4.2 E2 1:N 개방형 식별

**프로토콜.**
- 엔진과 같은 파이프라인(SCRFD 5점 → norm_crop → 임베딩)에 고객별 최대 점수를 쓰고, top1 ≥ T와 margin 규칙으로 판정했습니다.
- 등록: CelebA in-the-wild 4,584명(템플릿 최대 4장). mated 검색은 78,657회입니다.
- 비동일인 검색: 등록하지 않은 CelebA 5,315명의 98,567회입니다.
- 갤러리 확장: 실사진 방해자 FFHQ와 합성 방해자 DigiFace-1M을 더해 최대 **149,392명 / 493,141 템플릿**까지 키웠습니다.
- CelebA 신원 라벨에 오류가 많아, 4개 모델이 모두 동의하는 경우에만 정리했습니다. 동일인 중복 id 235개와 probe 3,993장을 제외했습니다.

| 모델 | FNIR @ FPIR 10⁻² | 10⁻³ | 10⁻⁴ [95% CI] | 100만×4 외삽: FPIR 10⁻⁶ 임계값 → FNIR (사진 1장 / 3장 평균) |
|---|---|---|---|---|
| **AdaFace IR101 (배포)** | 2.04% | 2.47% | **3.28%** [3.16, 3.41] | 0.597 → **13.5% / 1.84%** |
| InsightFace R50 | 2.21% | 2.78% | 3.63% [3.50, 3.76] | 0.578 → 14.2% / 1.94% |
| KP-RPE ViT-B | 2.01% | 2.57% | 3.64% [3.52, 3.78] | 0.639 → 25.2% / 4.46% |
| InsightFace R100 | 2.10% | 3.44% | 24.59% | 꼬리가 두꺼워 결정 불가 |

- **입증 한계.** 98,567회 검색에서 오류가 0건이어도 입증되는 FPIR 상한은 3.0×10⁻⁵입니다. 10⁻⁶을 입증하려면 무오류 독립 검색이 2,995,731회 필요합니다. 표의 외삽 값은 타인 점수 꼬리(GPD)와 비교 독립을 가정한 **모델 기반 추정이지 측정이 아닙니다.** 측정 가능한 구간에서는 이 외삽이 실측 FPIR과 0.7–1.4배 범위로 맞았습니다.
- **오식별.** 등록 고객이 다른 등록 고객으로 식별된 경우(RFP가 별도 집계를 요구한 항목)는 FPIR 10⁻⁴, margin 0에서 5건이었고 margin 0.08 이상에서는 0건입니다. 배포값은 margin 0.10입니다.
- **갤러리 규모 영향.** 4,584명에서 149,392명으로 키워도 FNIR@FPIR 10⁻⁴는 3.18%에서 3.28%로 거의 그대로였습니다. 다만 FFHQ·DigiFace 방해자는 유명인 probe와 잘 헷갈리지 않으므로, 실제 고객 갤러리보다 쉬운 조건입니다.
- **FNIR이 높게 나온 이유.** 웹 사진 1장(측면·노화·저화질)을 probe로 썼기 때문입니다. 키오스크는 같은 세션의 협조적 정면 프레임을 평균하므로 실제 FNIR은 3장 평균 쪽에 가까울 것으로 예상하지만, 현장 데이터로 다시 재야 합니다.
- **편향 경고.**
  - CelebA는 유명인이라 학습 신원과 겹쳐 결과가 낙관적입니다.
  - 일반인(FFHQ) probe는 같은 임계값에서 오수락이 수십 배 많았습니다(영유아 포함).
  - 동아시아 전용 시험셋이 없습니다. InsightFace 공개 모델은 동아시아에서 크게 약했습니다(MR-ALL 74.96 vs 94.70). 한국 고객 대상 재측정이 필수입니다.

- **v1 → v2**: 초기 모델(v1)은 정면 사진으로만 학습해서, 등록에 필요한 좌·좌상·우상 방향 프레임의 33–67%를 위조로 판정했습니다.

- 장애 전환 뒤 이미 반영한 이벤트가 사라지거나 번호가 재사용된 것을 검색 복제본이 감지하면 색인을 재구성하도록 보강했습니다.
- 한계: 단일 호스트이므로 네트워크 분할·디스크 손실은 시험하지 못했습니다.

## 6. 한계와 다음 단계

**이번 단계의 한계**
1. 센서·공격·사용자가 모두 시뮬레이션입니다. PAD 수치와 등록 성공률은 실환경 성능이 아닙니다.
2. 1:N은 공개 유명인 데이터 14.9만 명 규모라, 목표(100만 명, FPIR 10⁻⁶)를 입증할 수 없습니다. 학습 신원 중복과 동아시아 데이터 부재로 낙관적입니다.
3. 단일 호스트·단일 GPU라서 실제 다중 노드 장애(네트워크 분할, 디스크 손실)와 다중 GPU 부하는 시험하지 못했습니다.
4. 임계값 일부(T_SAME, 눈 감김 기준)는 평가 인물로 조정했습니다. 독립 데이터로 재검증해야 합니다.

**하드웨어·파일럿 단계 권고**
1. 실센서(Gemini 336 또는 양산 보안 모듈)로 실제 공격물(인쇄·화면·3D 마스크)을 포함한 RGB-D-IR 데이터를 수집합니다. 학습·검증·시험 인물을 분리합니다.
2. PAD를 재학습하고, 세션 단위 판정 규칙을 보정합니다. ISO/IEC 30107-3 독립 시험을 받습니다.
3. 센서 출처 증명(카메라 모듈 내부 서명)을 확보하고, 캡처 경로 주입을 시험합니다.
4. 동의를 받은 현장 1:N 데이터를 모읍니다. 한국인 인구 구성으로 등록 세션과 인증 세션을 분리하고, 약 300만 회의 독립 비동일인 검색 시험을 계획합니다. 모델과 임계값은 시험 전에 고정합니다.
5. 상용 권리를 확보합니다: InsightFace 상용 라이선스/비공개 모델, 또는 동의 데이터로 자체 학습.
6. 운영 규모 GPU를 산정합니다: 초당 100세션 기준 엔진 GPU 2장 + N+1로 시작하고, 동적 배치·TensorRT 확대로 재측정합니다.
