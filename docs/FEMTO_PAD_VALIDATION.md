# Femto Bolt PAD 상태와 검증 참고 자료

2026-10-15 사용자의 추가 수집 없는 개선·배포 요청에 따라, 내부망 데모는
**실측 미검증 실험용 PAD**(`pad_enabled=true`, `pad_mode=femto_geometry_experimental`)를 사용합니다.
이 모드는 프레임별 깊이 검사를 실제 인증에 적용하지만, 수정된 계산의 실제 사람 통과율이나
사진·화면 공격 방어율을 검증했다는 뜻은 아닙니다. 2026-10-16 사용자 요청으로 등록에는 PAD를 적용하지 않습니다.
등록 화면은 **등록 PAD 꺼짐**을 표시하고, PAD 수집 화면에는 실측 미검증 안내를 유지합니다.
라이브 화면의 상태 배지는 사용자 요청으로 제거했으며 인증 PAD 적용 설정은 유지합니다.
기존 production 검증 gate와 검증된 pilot 경로는 그대로 유지하며, 새 모드가 이를 통과한 것으로 처리하지 않습니다.

2026-10-16 등록 촬영 3회가 각각 18프레임·9방향을 완료한 뒤 `pad_fail`로 거절된 것을 감사 기록에서 확인했습니다.
세부 깊이 수치는 저장되어 있지 않아 실패한 특징이나 임계값을 특정할 수 없습니다. 처음에는 등록 안내에 같은 검사를
추가했으나, 후속 요청에 따라 촬영 안내와 최종 등록 모두에서 PAD를 제외했습니다. 기본 영상 품질·단일 얼굴·
9방향 촬영·동일인·동의·서명 검사는 유지합니다. 이 변경은 인증 PAD를 우회하지 않습니다.

## 위치 오차 개선과 실험 배포

v2 특징은 코 랜드마크 주변의 제한된 범위에서 패치 중앙값으로 코 위치를 찾고 주변 곡면을 다시 맞춥니다.
가로·세로 양쪽의 국소 돌출을 함께 확인해 길게 이어진 접힘을 구분하고, 지지되는 깊이 영역 안에서
급격한 단차가 있으면 측정을 거절합니다. 원본 깊이·IR·영상은 메모리에서만 처리합니다.

`FemtoPADExperiment`는 새 처리 코드·검출기·센서 보정과 정확히 일치하는 별도 설정 파일을 사용합니다.
API와 엔진에 동일한 `FA_PAD_MODE=femto_geometry_experimental`, `FA_FEMTO_PAD_PROFILE_SHA256`을 설정하고,
엔진의 `FA_FEMTO_PAD_PROFILE`은 읽기 전용 설정 파일을 가리킵니다. `FA_PILOT_DISABLE_PAD=0`입니다.
인증에서는 설정·센서·코드가 다르거나 깊이 측정이 실패하면 승인하지 않으며, PAD 꺼짐으로 자동 전환하지 않습니다.
승인 토큰과 단말 결과에도 실험 모드와 설정 SHA를 포함합니다. 인증에서 선택된 3프레임은 모두 통과해야 합니다.

2026-10-16 인증 판정 최소값을 사용자의 완화 요청에 따라 아래처럼 조정했습니다.

| 깊이 특징 | 이전 값 | 현재 값 |
|---|---:|---:|
| 평면 잔차 | 0.353601997mm | 0.30mm |
| 코 주변 국소 깊이 차 | 4.563589938mm | 3.0mm |

두 조건을 동시에 만족해야 하며, 측정 커버리지·IR 누락·깊이 단차 거절은 유지합니다.
설정에는 이전 값과 `operator_requested_engineering_relaxation` 이력을 남깁니다.
이는 실측 v2 표본에 맞춰 보정한 값이 아니므로 `empirical_validation=not_evaluated`, `production_validated=false`입니다.
`pad_experiment.ready`는 설정 일치를 뜻하고, `pad_validation.ready` 또는 과거 pilot 적격 판정을 대신하지 않습니다.

기존 103회 관측에는 수치만 있어 v2를 다시 계산할 수 없습니다. 이번 배포에서는 추가 표본을 수집하지 않고,
원본 관측·실패한 실제 시험·고정 v1 프로필을 변경하지 않습니다. v1 기록은 v1로 읽고 v2와 혼합하지 않습니다.
합성 위치 오차·평면·접힘·단차·누락 검사는 계산의 회귀 검증이며 실물 공격 시험을 대체하지 않습니다.
아래의 표본 수집·pilot 검증 절차와 과거 결과는 별도 검증 경로의 참고 자료입니다.

## 인증 실패 진단 기록

2026-10-16 이번 배포 이후 새 인증의 `auth_decision` 감사 기록에는 `detail.pad_diagnostics`를 추가합니다.
기존 `pad_fail`과 판정은 유지하고, 화면이나 공개 인증 응답에는 세부 진단을 노출하지 않습니다.

- `total_frames`, `passed_frames`, `failed_frames`: 검사 대상·통과·실패 프레임 수.
- `nonresponse_frames`: 실패 중 깊이·IR 등을 측정할 수 없었던 프레임 수.
- `unmeasured_frames`: 품질·설정 등의 이유로 PAD 결과가 없었던 프레임 수.
- `reason_counts`: `nose_protrusion_mm`, `plane_residual_mm`, `nose_coverage`, `depth_blocks`,
  `nose_depth_discontinuity` 등 고정된 조건별 실패 횟수. 같은 프레임의 같은 이유는 한 번만 셉니다.

전체 수는 통과+실패+미실행 수의 합입니다. 최대 16프레임만 집계하고 초과 여부는 `truncated`로 표시합니다.
등록이나 신원 검색 전의 실패를 특정 사람의 실패로 추정해 기록하지 않습니다. 이 진단에는 영상·랜드마크·
임베딩·깊이 특징값·점수를 추가 저장하지 않습니다. 이전 기록에는 세부 조건이 없으므로 소급 복원하지 않습니다.
추가 표본 수집 화면을 실행할 필요 없이 이후 정상 인증 시도에서 내부 집계가 남습니다.
추론 전 실패와 의존 서비스 오류에는 완료된 PAD 결과가 없어 측정 횟수를 만들지 않습니다.
관련 회귀 검사 393개와 합성 브라우저 검사 61개를 통과했으며, 배포 후 두 API·GPU 엔진과
카메라 약 30 FPS 수신을 확인했습니다
([배포 확인 기록](../reports/deployment/femto_bolt_auth_diagnostics_deadline_deployment_20261016.json)).

## Femto 깊이 PAD 시험 후보

`faceauth/models/femto_pad.py`는 정합된 깊이와 SCRFD 5점으로 얼굴 내부의 깊이 형태를 측정합니다.
역깊이 평면을 맞춰 기울어진 사진의 경사를 제거하고, 이차 곡면 잔차와 주변 표면 대비 코 돌출량을
구합니다. 얼굴 전체·코·주변 표면의 깊이 커버리지가 부족하면 비응답으로 처리합니다.
IR은 누락 확인과 수치 진단에만 쓰며, 피부라는 증거로 해석하지 않습니다.

이 후보의 범위는 **인쇄물·화면 재생에 대한 내부망 시험**입니다. 실제 입체 가면의 생체 여부를
확인하는 모델이 아니며, 휘어진 사진이나 센서 잡음에 대한 실제 성능도 표본 시험으로 확인해야 합니다.
합성 평면·곡면 테스트는 계산 검증이며 실제 공격 방어율이 아닙니다.

관측 결과의 `pad_candidate.valid`는 **수치를 계산할 수 있었다**는 뜻이며 PAD 통과가 아닙니다.
새 `candidate_binding`은 특징 코드·검출기·수집/판정 코드의 SHA-256을 고정합니다. 기존 CNN의
`pad`, `model_binding`, 정식 `pad_validation`은 별도로 유지합니다. 이전 32회 기록에는 이 새
특징이 없고 원본도 없으므로 새 후보의 보정 표본으로 재사용할 수 없습니다.

### 실제 표본과 적용

1. 웹 상단의 **PAD 표본 수집** 버튼을 누르면 카메라와 수집 설정이 나란히 있는 전용 화면이 열립니다.
   [수집 화면 바로가기](http://192.168.2.218:8080/#pad)도 사용할 수 있습니다.
   수집 화면 안에서 계정을 선택하고 **PAD 검증용 수치 표본 수집**에 동의한 뒤
   `깊이·IR 측정 · 5프레임`을 선택합니다. 대상 코드는 이름 대신 `subject-001`처럼
   공백 없는 익명 코드를 씁니다. 버튼 위에 미완료 조건이나 입력 오류가 표시됩니다.
   `실제 사람`, `인쇄 사진`, `화면 재생`을 각각 별도 시도로 촬영합니다. 공격 매체에는 식별 코드를
   붙입니다. 얼굴이 잡히지 않거나 깊이가 부족한 프레임도 기록합니다. 원본 영상은 저장하지 않습니다.
2. 보정(`calibration`)은 종류별 최소 3시도를 사용합니다. 50–80cm에서 거리·기울기·위치를 달리하고,
   여러 참여자와 매체를 포함하는 편이 좋습니다. 얼굴 특징과 공격 특징이 겹치면 보정은 거절됩니다.
   단순히 임계값을 낮춰 통과시키지 않습니다.
3. 보정 프로필을 고정한 뒤 시험(`test`)에서 종류별 최소 3개의 새로운 시도를 기록합니다.
   시험 자료로 임계값을 다시 맞추지 않습니다. 가능하면 사람과 매체도 보정 자료와 분리합니다.
   같은 사람·매체가 겹쳤다면 그 사실을 기록하며 독립 시험이라고 주장하지 않습니다.
4. 시험의 실제 사람 3회 중 최소 한 번은 `인증 · 3프레임`, 한 번은 `등록 · 18프레임` 관측으로
   진행합니다. 인쇄물·화면도 각각 최소 한 번은 인증 관측으로 측정되어 거절되어야 합니다.
   진단만 있는 보고서는 적용할 수 없습니다. 관측은 얼굴을 등록하거나 승인 토큰을 발급하지 않습니다.

최소 3시도는 이 시험 기능의 기초 점검 기준일 뿐, 표준 인증이나 낮은 공격 통과율을 입증하는
표본 수가 아닙니다. 평가 보고서는 시도 단위 오류·비응답·95% 상한을 함께 남깁니다.

```bash
python scripts/calibrate_femto_pad.py fit \
  --observations consented-study.jsonl \
  --calib-version femto-bolt-v1-50beeef1ae82fb27 \
  --output calibrated-profile.json

# 프로필을 고정한 후 새로운 test 시도를 수집하고 실행합니다.
python scripts/calibrate_femto_pad.py evaluate \
  --observations consented-study-with-test.jsonl \
  --profile calibrated-profile.json --output evaluated-profile.json
```

CLI는 새 특징이 없는 과거 관측을 제외하고 그 개수를 출력합니다. 후보 코드 버전이 여러 개면
`--candidate-binding`으로 사용할 버전의 바인딩 JSON을 명시합니다. 기존 출력 파일은 덮어쓰지 않으며,
출력은 기본 `0600`입니다. 배포할 때 엔진 UID가 완성된 프로필을 읽을 수 있도록 소유권을 설정합니다.

적용 모드는 `FA_PAD_MODE=femto_geometry_pilot`입니다. `FA_FEMTO_PAD_PROFILE`은 컨테이너의
읽기 전용 프로필 경로, `FA_FEMTO_PAD_PROFILE_SHA256`은 완성된 파일의 SHA-256입니다.
API와 두 엔진에 동일한 모드·해시를 적용해야 합니다. 파일 누락·변조·센서 또는 파이프라인 변경·
시험 미완료는 인증을 차단합니다. 승인 토큰·감사 기록에도 모드와 프로필 해시가 남습니다.
화면에는 **깊이 PAD · 시험 적용**과 사진·화면 범위가 표시됩니다. 라이브 이름 박스는 여전히
신원 인식 데모이며 PAD 승인 표시가 아닙니다.

이 모드의 `pad_pilot_validation`은 로컬 시험 결과만 나타냅니다. 정식 `pad_validation.ready`를
참으로 바꾸거나 독립 시험을 대신하지 않습니다. 기본 `enabled` 모드는 아래의 정식 검증 조건을
계속 요구합니다. `FA_PAD_MODE`를 비우면 기존 `FA_PILOT_DISABLE_PAD` 설정으로 돌아갑니다.

별개입니다. 시험 때는 카메라 렌즈부터 휴대폰 화면 표면까지 50–80cm를 확보해야 합니다.
저장된 센서 수치만으로 실제 물리 거리를 확정할 수는 없습니다.

### 라벨 정정과 첫 진단 시험 결과

사용자가 실제 사람을 화면 재생으로 잘못 기록했다고 확인한 첫 시험 6회는 대상 종류만
`replay`에서 `live`로 정정하고 공격 매체 코드를 비웠습니다. 실제 촬영 방식 `diagnostic`,
용도 `test`, 프레임·수치·동의·식별자는 유지합니다. 원본 JSONL과 고정 프로필은 수정하지 않습니다.

### 실제 촬영 절차의 제한된 시험 계획

바로가기 수정 후 실제 등록 선택 경로의 9방향 18프레임이 모두 측정되고 기존 기준을 통과했습니다.
정면 선택 경로 12프레임과 합쳐 실제 사람 보정 관측 5시도·30프레임이 통과한 것입니다.
[등록 선택 경로 확인](../reports/deployment/femto_bolt_pad_enrollment_path_review_20261015.json).
이는 기존 진단의 실제 사람 거절 1회를 해결했다는 뜻이 아닙니다. 진단의 자세 실패가 인증 범위
밖이라는 점만으로 더 넓은 등록 범위에서도 안전하다고 단정할 수 없으며, 이 한계를 계속 보고합니다.

다음 시험은 사전에 범위를 고정한 **실제 인증 공격 시험 및 실제 사람 등록 동작 확인**입니다.
원본 관측 파일의 시작 경계·해시, 정정 파일, 고정 프로필, 처리 코드, 기존 진단 실패 보고서를
시험 계획에 연결한 뒤 새로운 `test` 관측만 수집합니다. 실제 사람은 인증 1회·전체 9방향 등록 2회,
인쇄 사진과 화면 재생은 인증 촬영 각각 3회로 정확히 총 9회입니다. 동일 참여자·매체 재사용과 작은 표본의
한계를 명시하며, 등록 경로의 공격 방어 성능이나 독립 인증 시험을 통과했다고 주장하지 않습니다.

계획 이후 해당 경로로 기록된 시도는 성공·실패·시간 초과·비응답 여부와 무관하게 모두 포함합니다.
계획보다 많은 시도도 기록에서 제외하지 않으며, 초과한 경우 이 시험 계획으로 적용하지 않습니다.
성공할 때까지 반복하여 실패를 대체하거나 기존 진단·보정 자료를 새 시험으로 바꾸지 않습니다.
촬영 모드가 다른 새 관측은 개수와 제외 근거를 별도 보고합니다. 기존 17회 진단 결과는 새 시험
결과와 함께 보존합니다. 취소·전원 분리처럼 기존 기록 경로가 남기지 못한 사건은 자동 JSONL만으로
알 수 없으므로 운영자가 별도로 알려야 합니다. 적용하려면 시작 9회·기록 9회·취소 0회·미기록 0회라는
현장 확인이 필요하며, 이 확인도 전체 시행을 기록한 독립 시험 대장을 대신하지는 않습니다.

적용 조건에는 기존 프로필 평가뿐 아니라 실제 사람의 최종 프레임 품질·프레임 수,
공격 종류별 최소 한 번의 품질 통과·수치 측정 가능 상태에서의 PAD 거절을 포함합니다.
조건을 만족하지 못하면 새 시험도 부적합으로 남기고 PAD를 켜지 않습니다. 새 시험이 통과하더라도
주장 범위는 감독 가능한 내부망 파일럿이며, 기존 진단에서 드러난 자세 관련 한계는 유지합니다.

`scripts/evaluate_femto_runtime.py`가 이 추가 시험을 선언하고 평가합니다. `create`는 수집 전에
한 번 실행하고, 출력된 계획 해시를 별도로 기록합니다. 이후 실패 시도를 제외하려고 계획을
다시 만들지 않습니다. `evaluate`는 전체 원본·기존 정정 내역을 읽고 계획 시점 이후의 해당
시도를 모두 포함합니다. 계획·원본 접두부·보정 프로필·정정·평가 코드가 달라지면 중단합니다.
부적합·표본 부족 결과도 보고서로 남기며, 모든 조건을 통과해야만 배포 가능한 프로필을 씁니다.

```bash
python scripts/evaluate_femto_runtime.py create \
  --observations consented-study.jsonl \
  --corrections consented-study-corrections.jsonl \
  --profile calibrated-profile.json --prior-report failed-diagnostic-report.json \
  --output runtime-protocol.json

python scripts/evaluate_femto_runtime.py evaluate \
  --observations consented-study.jsonl \
  --corrections consented-study-corrections.jsonl \
  --profile calibrated-profile.json --prior-report failed-diagnostic-report.json \
  --protocol runtime-protocol.json --protocol-sha256 "$PAD_RUNTIME_PROTOCOL_SHA256" \
  --attempt-reconciliation operator-confirmed-attempts.json \
  --report runtime-report.json --output-profile runtime-evaluated-profile.json
```

`--attempt-reconciliation`은 실제 촬영자의 완료·취소·미기록 확인을 받은 뒤 작성합니다.
확인이 없거나 계획·기록과 맞지 않으면 보고서만 생성하며 배포 프로필은 생성하지 않습니다.

### 실제 촬영 경로 시험 결과: 등록 오판정으로 적용 중단

### 후속 개발 분석: 아직 대체 판정 없음

현재 코 특징은 RGB 코 기준점 주위의 작은 영역을, 카메라 깊이 방향의 기준 곡면과 비교합니다.
충분한 깊이 점이 있다는 검사만으로 해당 영역이 실제 코 끝인지는 알 수 없습니다. 합성 자료에서
코 기준점 위치 오차에 따른 점수 저하를 재현했지만, 실제 기록의 원인이 자세·정합·검출 오차 중
무엇인지는 원본 영상 없는 수치만으로 확정하지 못했습니다.

평면 잔차와 이차 곡면 잔차를 함께 보는 대안도 기존 수치로 개발 분석했습니다. 보정 자료의
최대 공격 프레임과 최소 사람 프레임의 중간값은 각각 `5.774808mm`, `3.062476mm`입니다.
이 조합은 기존 사람 시도를 모두 통과시키고 공격 시도는 모두 거절하지만, 인쇄물의 한 프레임은
두 잔차가 `41.543mm`, `30.414mm`로 커서 대안을 통과합니다. 같은 프레임의 깊이 IQR은
`118mm`이며 코 돌출량은 `-50.250mm`입니다. 측정 불연속이나 배경 혼입이 굴곡으로 보일 수 있어,
단순히 코 조건을 빼거나 잔차 조건으로 바꾸는 것을 해결책으로 적용하지 않았습니다.
[수치 기반 대안 분석](../reports/deployment/femto_bolt_pad_surface_development_20261015.json).
이 분석에 사용한 과거 시험 자료는 새 판정의 개발 자료이며, 독립·새 최종 시험으로 재사용하지 않습니다.

`scripts/diagnose_femto_nose.py`는 실제 카메라 없이 31개 합성 깊이 조건을 수치로 재현합니다.
128×128 합성 영상에서 코 기준점을 8픽셀 옮기면 측정 가능 상태를 유지하면서 코 돌출량이
`17.61mm → 1.85mm`로 낮아집니다. 이는 원본 Femto 영상의 8픽셀 오차를 뜻하지 않습니다.
이상적인 3D 회전만 적용한 장난감 곡면에서는 해당 음수 점수가 재현되지 않아, 실제 실패를
회전 자체의 결과라고 단정할 근거도 없습니다. 또 100mm 깊이 단차는 평면 잔차 `26.57mm`,
이차 잔차 `26.33mm`, 코 돌출량 `33.69mm`를 만들면서 측정 가능 판정을 받습니다.
따라서 큰 굴곡·양의 코 값만으로 생체를 입증할 수 없습니다.
[합성 진단 수치](../reports/deployment/femto_bolt_pad_nose_synthetic_20261015.json).

합성 진단 및 기존 특징 계산 테스트 53개가 통과했습니다. 이 테스트는 특징의 한계와 수치
동작을 재현하는 것으로 실제 PAD 성능 시험이나 해결 완료를 뜻하지 않습니다. 대체 분류기,
임계값 완화, 넓은 영역의 최대 깊이 값으로 통과시키는 경로는 추가하지 않았습니다.
다음 후보에는 깊이 표면의 공간적 연속성과 코 위치 신뢰성을 먼저 반영해야 하며,
그 후보를 고정하기 전에는 같은 최종 시험을 더 요청하지 않습니다.

## 현재 차이

| 항목 | 기존 학습·평가 | Femto Bolt 현재 캡처 |
|---|---|---|
| 보정 | `gemini336-sim-v1`, fx 385 | `femto-bolt-v1-50beeef1ae82fb27`, 출력 컬러좌표 fx 약497.406 |
| 깊이 | 합성 얼굴 메쉬/센서 오차 | 실제 ToF, 가림·반사·멀티패스·무효점과 컬러좌표 재투영 |
| IR | 합성 uint8, 얼굴 반사율·음영 가정 | Y16, 고정 `log1p` 곡선으로 uint8 변환 |
| 랜드마크 | 합성 정답 5점 | 엔진 SCRFD 검출 5점 |
| PAD 사용 시 평가 단위 | 단일 프레임 | 등록·인증 시도의 모든 선택 프레임이 live여야 함 |

PAD는 RGB 3채널, 상대깊이, 유효깊이 마스크, IR의 6채널 CNN과 물리 검사를 함께 씁니다.
현재 임계값은 0.9994763732이며 깊이 유효비율≥0.5, 잔차 relief≥3mm,
IR 중앙값≥30, 음영 상관≥0.1이 필요합니다. 이 수치는 합성 분포에서 정한 것입니다.
fx는 깊이 표면 기울기·IR 음영 상관 계산에 직접 들어갑니다. fx만 고치거나 IR 기준을
낮추거나 보정 이름을 바꾸어도 실제 성능 증적이 생기지 않습니다.

현재 NFOV 640×576 모드의 공식 동작 범위는 0.5–3.86m입니다. 초기 현장 실험은
50–80cm에서 수행하고, 그보다 가까운 구간은 별도 검증합니다.
[Orbbec 공식 하드웨어 사양](https://doc.orbbec.com/documentation/Orbbec%20Femto%20Bolt%20Documentation/Femto%20Bolt%20Hardware%20Specifications).

## PAD를 다시 사용할 때의 검증 참고 절차

다음 절차는 기본 `enabled` 모드의 정식 검증 절차입니다. 깊이 PAD 로컬 시험과 구분합니다.
이 모드에서는 점수 진단과 인증 승인을 구분하고,
검증 자료가 없는 모델의 등록 완료·인증 승인 토큰 발급을 차단합니다.

1. 참여자가 **점수 기반 PAD 실험**의 목적과 저장 항목에 명시적으로 동의합니다.
   참여자·동의·시도 식별자는 계정명 대신 실험용 무작위 ID를 사용합니다.
2. 실제 얼굴을 50/65/80cm, 정면과 등록의 주변 8방향, 일반/어두운/측광 조건에서
   측정합니다. 안경·표정·다른 날짜·다른 참여자를 포함하고 각 시도를 새로 시작합니다.
   실패·얼굴 미검출·센서 무효·중도 포기도 기록해야 성공 표본만 남는 편향을 줄일 수 있습니다.
3. 동의받은 얼굴 자료로 물리 공격을 준비합니다. `print`: 평면/휘어진 무광·유광 인쇄물,
   `replay`: 서로 다른 휴대폰·태블릿·모니터의 정지영상/동영상,
   `mask_rigid`: 실제 입체 경질 가면, `mask_silicone`: 실제 유연한 실리콘 가면.
   각 물체에 `instrument_id`를 부여합니다. 공격 종류·재질·장소별 결과를 분리합니다.
   가면이 없으면 해당 공격 범위는 **미시험**으로 남깁니다.
4. 학습/보정/최종시험의 사람과 물리 공격 도구를 분리합니다. 모델·임계값을 먼저 고정하고
   최종시험을 실행합니다. 인접한 30 FPS 프레임 300장은 독립 시도 300회가 아닙니다.
5. 현재 세 관측 모드의 수집은 원본·임베딩을 저장하지 않는 점수 측정입니다. 모델 재학습은 별도 원본 수집 동의,
   보관·철회·삭제 방식, 합법적 사용 권한을 정한 후 진행합니다. 점수만으로 CNN을 재학습할 수 없습니다.

위 목록은 현장 진단 계획이며 표준 인증 시험을 대체하지 않습니다. 사진·영상·가면별 오류율은
서로 대체할 수 없습니다. NIST의 소프트웨어 RGB 평가도 공격 도구 종류별 차이를 보고하며,
그 성적을 이 RGB-D-IR 모델에 적용할 수는 없습니다.
[NISTIR 8491](https://nvlpubs.nist.gov/nistpubs/ir/2023/NIST.IR.8491.pdf).

## 웹/엔진 기록 계약

`faceauth.common.pad_validation.make_observation`은 센서를 열거나 파일을 쓰지 않습니다.
웹은 동의를 받은 뒤 라이브 워커의 새 시도 프레임을 엔진 observe 경로에 전달하고,
반환된 `model_binding`과 프레임 측정을 다음처럼 전달합니다.

```python
row = make_observation(
    presentation_id="random-attempt-id", subject_id="study-person-01",
    consent_id="random-consent-id", consent=True,
    kind="live", split="calibration", instrument_id=None,
    calib_version=verified_packet_calibration,
    binding=engine_response["model_binding"], frames=engine_response["frames"],
    conditions={"mode": "diagnostic", "distance_mm": 650, "lighting": "indoor",
                "pose": "C", "location_id": "room-A", "eyewear": "none"},
)
```

`kind`는 `live|print|replay|mask_rigid|mask_silicone`, `split`은
`train|calibration|test`입니다. `frames`에서 보관되는 값은 PAD의
`score/live/nonresponse/cnn/checks/failed`와 품질/실패 사유뿐입니다.
RGB·깊이·IR·랜드마크·임베딩·계정 주장은 제외합니다. PAD 자체가 수행되지 않은 프레임은
비응답으로 남습니다. `binding`은 모델 메타데이터·가중치·검출기 및 처리 코드 hash를 묶습니다.
이 기록은 여전히 실험 참여 기록이므로 제한된 보관 기간과 삭제 절차를 적용해야 합니다.

웹 `/api/auth/observe` 요청의 `observation_mode`는 다음 세 모드를 지원합니다.

| `observation_mode` | 프레임 수집 | 기록의 `conditions.mode` |
|---|---|---|
| `diagnostic` (기본) | 품질 불합격도 포함한 고정 간격 정면 5프레임 | `diagnostic` |
| `auth` | 실제 인증과 동일한 정면·품질 선택기의 3프레임 | `auth` |
| `enroll` | 실제 등록과 동일한 Guide의 9방향별 2프레임, 총18프레임 | `enroll` |

웹이 선택한 모드의 실제 프레임 선택 과정을 수행하고, 해당 모드로 측정 기록을 만듭니다.
이미 수집한 진단 5프레임의 라벨을 `auth`나 `enroll`로 바꾸어 대신하지 않습니다.
모든 관측 모드는 동의 후 점수·물리 검사만 저장하며 얼굴 등록, 템플릿 생성, 인증 승인 또는
승인 토큰 발급을 하지 않습니다. PAD가 아직 미검증이어도 `capture_ready`이면 관측할 수 있지만,
PAD 사용 모드의 등록·인증 `ready` 조건은 그대로 유지됩니다. `observe`는 별도의 진단 경로로
PAD 비활성 파일럿에서도 PAD를 측정할 수 있지만, 현재 사용자 등록·인증 흐름에서는 사용하지 않습니다.

이는 실제 선택 경로의 자료를 수집할 수 있도록 구현한 기능이며 현장 검증 완료를 뜻하지 않습니다.
이미 수집한 32시도를 포함한 `diagnostic` 자료는 승인 근거 통계에 포함하지 않습니다.
`auth`/`enroll` 자료도 아래의 독립 시험·분할·표본·오류 상한 조건을 충족해야 합니다.
`diagnostic_summary`는 별도 진단용입니다.
진단 요약은 보정/시험 자료 모두 보여주고 `diagnostic_by_split`으로 구분합니다. 승인 통계는
오직 최종시험 split의 실제 인증/등록 시도만 사용합니다.
각 요약의 `diagnostics`에는 CNN/최종 점수와 IR·relief·음영 상관 등의 5/50/95백분위수,
검사별 실패 프레임 수를 담습니다. 이 프레임 분포는 센서 도메인 차이를 진단하기 위한
값이며 독립 표본 수나 정확도 신뢰구간을 늘리지 않습니다.

품질·얼굴 안내를 한 번 이상 수행한 `auth`/`enroll` 관측이 안내 시간 초과 또는 세션 만료로
끝나면 그 시도도 비응답으로 저장합니다. 기록의 `conditions.capture_outcome`은
`selection_timeout` 또는 `session_expired`이고, 점수는 `null`이며 실패 사유가 남습니다.
이 명시적인 미측정 표시는 시도 분모와 비응답률에만 포함하고 실제 측정 프레임 수·물리 수치
분포에는 포함하지 않습니다. 시작과 종료에 직접 조회한 엔진 모델 binding·센서 보정이 같아야
기록하며, 모델 재적재 중인 결과를 새 모델의 관측으로 바꾸어 저장하지 않습니다.
사용자가 직접 취소한 촬영은 PAD 오판정이나 비응답으로 계산하지 않고 저장하지 않습니다.
취소, 카메라 분리, 서버 장애, 모델 변경 등 측정을 끝내지 못한 사건은 현장 운영자가 별도
시도 대장에 남겨야 합니다. 자동 JSONL만으로 전체 참가·중도 포기 현황을 알 수는 없습니다.

## PAD 재검증 시 현장 측정 방법

웹에서 별도 테스트 계정을 만들고 로그인한 뒤 촬영 동의와 **센서 검증**을 선택합니다.
GPU 엔진이 준비되어 `capture_ready`가 참이면 최종 인증 승인이 막혀 있어도 측정할 수 있습니다.
먼저 대상 코드를 무작위로 정하고 `calibration`/`live`/`diagnostic`으로 50–80cm 정면 측정을
시작합니다. 같은 위치에서 동의받은 얼굴의 인쇄물과 다른 화면 재생을 각각 독립 시도로 측정하고
공격 매체 코드를 달리 기록합니다. 이어 `auth`, `enroll` 모드의 실제 안내를 수행합니다.
이 첫 진단은 센서 입력과 모델의 차이를 확인하기 위한 것으로, 한 사람의 성공이나 사진 한 장의
거절만으로 PAD 검증 완료를 선언할 수 없습니다. 최종시험 사람·매체는 보정 자료와 분리합니다.

운영자가 점수 기록을 호스트로 복사할 때는 다음 명령을 사용합니다. 실제 기록이 생긴 뒤에만
실행하며, 내보낸 파일에도 서버 기록과 같은 접근·보관·삭제 정책을 적용합니다.

```bash
docker compose -f compose.live.yml exec -T terminal \
  cat /var/lib/paceauth/pad-observations.jsonl > consented-study.jsonl
```


검증 미완료는 종료 코드 2입니다. 두 번째 명령은 실제 표본이 있을 때 실행합니다.
아직 없는 공격·최종시험 자료를 합성 관측 파일로 대신하지 않습니다.
보고서는 최종시험 split만 평가하고, 모든 프레임 live 규칙을 시도 단위로 적용합니다.
공격별 APCER, 생체 BPCER, 비응답률, 전체 시도 중 통과율과 각각의 **단측 95%
Clopper–Pearson 상한**을 계산합니다. 0회 오류라도 표본이 적으면 상한은 큽니다.
독립성은 ID 중복 검사만으로 입증되지 않으므로 실제 시험 운영자가 확인해야 합니다.

`RFP_KO.md` §4는 PAD 한계값을 별도 합의하도록 요구합니다. 기본 합격 수치나 기본 합격
표본수는 없습니다. 평가에서 다음 정책을 명시적으로 제공해야 합니다 (`--policy FILE`):

- `reference`, `approved_by`: 승인된 시험 계획/운영 담당자
- `required_species`: 네 물리 공격 유형 전체
- `required_modes`: `enroll`, `auth` 모두. 두 흐름의 프레임 선택/포즈가 달라 각각 평가합니다.
- `min_live_presentations`, `min_attack_presentations`, `min_live_subjects`, `min_attack_instruments`
- `max_apcer_upper95`, `max_bpcer_upper95`, `max_apnrr_upper95`, `max_bpnrr_upper95`

이와 함께 `--independent-test FILE`에 독립 시험의 `assessor`, `report_id`,
`report_sha256`, `independent: true`가 필요합니다. 서명 전에 실제 보고서와 현장 범위,
표본 독립성, 합의한 판정 기준을 담당자가 검토해야 합니다. 이 JSON 선언 자체가
독립 시험 수행이나 ISO 인증을 증명하지는 않습니다.

최소 표본수와 오류 상한은 전체 요약 및 각 모드 요약에 모두 적용합니다.
검출기는 엔진이 실제 로드한 디렉터리를 gate의 `detector_dir=`와 CLI의 `--detector-dir`에
전달합니다. 생략할 경우 registry에 검출기 버전이 하나일 때만 자동 선택합니다.

모델 후보가 정식 학습/보정·독립 평가를 마친 후에만 별도 release 검토를 실행합니다.
`sign --report ... --model-dir ... --release-key ...`는 조건을 충족한 보고서에만
Ed25519 서명을 추가하고, 평가 명령은 키를 읽거나 서명하지 않습니다.
기본 배포 위치는 해당 모델 디렉터리의 `PAD_VALIDATION.json`과 `.json.sig`입니다.
신뢰하는 release 공개키로 서명이 검증되고, 모델/가중치/처리코드/센서 보정이 일치하고,
정책·독립 시험·표본·오류율 조건이 모두 충족되어야 gate가 ready를 반환합니다.
모델 자체는 기존 서명 registry를 통해서도 별도로 검증됩니다.

PAD 사용 모드의 런타임은 `PADValidationGate(model_dir, release_pub).status(calib_version)`의
`ready/reasons`를 사용합니다. 승인 gate가 통과해도 각 등록/인증 시도의 기존 PAD·품질·신원
검사를 계속 수행합니다. 영상 주입·재전송·단말 변조 방어는 이 물리 PAD 평가와 별도로 시험합니다.
