# 1. 논리 구성 및 처리 배치

| 계층 | 담당 기능 | 기준 구성 |
|---|---|---|
| 센서 | RGB·Depth·IR 시퀀스 수집, 노출·동기화·보정 확인 | Gemini 336 평가용 / 양산 보안 모듈 별도 선정 [6] |
| 전용 단말 | 얼굴 추적, 회전 UI, 품질 확인, 동기화된 프레임 묶음 전송 | SCRFD-34G + 6DRepNet360 + FaRL 448px [1][2][3] |
| 중앙 GPU | 촬영 품질 재확인, 3센서 PAD, 얼굴 특징 추출 | ViT-L / WebFace42M 우선 후보. KP-RPE ViT-B와 경쟁 [4][5] |
| 식별·승인 | 1:N 검색 → 고객별 점수 통합 → 계정·권한 확인 → 승인 | FAISS 정확 검색 + 별도 인증 정책 서비스 [7] |
| 저장·운영 | 템플릿·동의·버전·계정 상태, 감사·키 관리 | PostgreSQL + 암호화 저장소 / 키 관리 서비스 분리 |

주 식별기는 RGB를 사용하고 Depth·IR은 PAD에 결합한다. 단말 → 서버는 mTLS로 보호하며, 서버가 선택된 3센서 원본 시퀀스를 메모리에서 재검증한다. 원본은 기본적으로 디스크에 저장하지 않고 세션 종료 시 폐기한다.
# 2. 등록 흐름
계정 소유 확인·동의 → 등록 세션/일회성 challenge 발급 → 정면 및 주변 8방향 안내 → 방향별 품질·동일인·PAD 확인 → 대표 템플릿 생성 → 중복 등록 검토 → 저장·인덱스 반영.
초기 각도는 좌우 약 ±25°, 상하 약 ±15°로 시험한다. 좋은 프레임으로 기본 4개 템플릿을 구성하며, 방향·시간·개수는 현장 검증 후 고정한다. 중복 후보만으로 계정을 자동 병합하지 않는다.
# 3. 인증 흐름 및 판정
인증 세션 발급 → 짧은 동기화 시퀀스 촬영 → 장치·세션·센서 품질 검증 → RGB·Depth·IR PAD → 정렬·특징 추출 → 1:N 식별 → 최종 권한 확인 → 해당 단말·행위에 한정된 단기 승인 발급.

| 승인 = 유효한 장치·세션 AND 촬영 품질 AND PAD 통과 AND 얼굴 식별 통과 AND 계정·권한 유효. PAD 실패를 높은 얼굴 유사도로 상쇄하지 않으며, Top-1이라는 이유만으로 승인하지 않는다. |
|---|

미등록·모호한 결과·센서 누락은 거절 또는 별도 인증으로 전환한다. 초기에는 단말·세션별 재시도를 제한하고, 고위험 업무는 고객 소유 인증 수단으로 추가 확인한다. 얼굴 단독 흐름을 다중요소 인증으로 표시하지 않는다. [8]

# 4. 모델·검색 설계
ViT-L은 정확한 가중치 확보와 상용 권리 확인 후 채택한다. KP-RPE는 공식 키포인트 입력·정렬 경로를 재현해 비교한다. FaRL의 정밀 랜드마크를 인식 정렬에 적용할 때는 최종 1:N 성능을 다시 검증한다. [3][4][5]
기준 검색은 정규화 벡터의 FAISS IndexFlatIP 전수 검색이다. 고객별 여러 등록·인증 프레임의 점수 통합 방식과 절대 임계값을 검증셋에서 고정한다. 근사 검색은 초기 비활성화하며, 도입 시 후보 누락·FPIR·FNIR을 재시험한다. [7]
# 5. 데이터 및 주요 API

| 인터페이스 / 데이터 | 핵심 계약 |
|---|---|
| POST /v1/sessions | 목적(enroll/auth), 장치 ID, 행위 ID → session_id, challenge, 만료 시각 |
| POST /v1/enrollments | 계정 확인 증거·동의 버전·촬영 묶음 → 템플릿 버전 및 등록 상태 |
| POST /v1/authentications | session_id·동기화 시퀀스·장치 증거 → 승인/거절/추가 인증. 검색 후보·점수는 외부에 미공개 |
| DELETE /v1/subjects/{id}/face | 권한 확인 후 즉시 승인 차단 → 템플릿·인덱스 삭제 확인; 백업 만료 정책 반영 |
| 템플릿 / 세션 레코드 | 가명 고객 ID, 암호화 벡터, 모델·정렬·센서 보정 버전, 동의·폐기 상태 / challenge 사용 여부·만료·판정 |

촬영 패킷은 session_id·challenge·장치 ID·프레임 순서·시각·보정 버전·원본 무결성 정보에 결합한다. 승인 발급과 challenge 소비는 원자적으로 처리해 재사용을 막는다.
# 6. 하드웨어 및 구현 기술

| 구분 | 평가·구현 기준 |
|---|---|
| 센서·단말 | Gemini 336의 RGB 1080p·Depth 1280×800·IR 동시 프로파일을 확인한다. 산업용 x86 + 32GB RAM + GPU로 시작; 40~80cm 품질·눈 안전·촬영 경로 보안을 검증한다. [6] |
| 중앙 서버 | GPU 추론과 검색 서비스를 분리·복제한다. 평가 노드당 GPU 24~48GB, RAM 128GB를 시작점으로 하며 GPU 수량은 부하 시험으로 확정한다. |
| 소프트웨어 | C++/카메라 SDK·OpenCV, PyTorch → ONNX Runtime/TensorRT, FAISS, gRPC/FastAPI, PostgreSQL. 버전 고정·서명된 배포를 적용한다. |

용량 산식: 100만 명 × 4개 × 512차원 × float32 = 벡터 원본 약 8.19GB. 복제·모델·작업 버퍼는 별도이며, 모델별 출력 차원 확정 후 재산정한다.
# 7. 보안·장애·모델 변경 정책
Secure Boot·보호된 장치 키·서명 업데이트를 적용하고 촬영 경로의 주입·변조를 별도 시험한다. TLS/서명만으로 센서 기원을 보증하지 않는다. 검색 메모리와 암호화 키를 격리하고, 센서·서버 장애 시 승인 조건을 완화하지 않는다. [8]
철회는 원장에서 즉시 승인 차단 후 인덱스·백업 정책에 반영한다. 모델·정렬·점수 집계·양자화 변경은 버전별 재시험을 요구한다. 비호환 벡터는 비교하지 않으며, 원본 미보관 상태의 모델 교체는 재등록 계획을 포함한다. 성능·검증은 동봉 RFP 4~5절을 따른다.
